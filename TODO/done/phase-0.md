# Phase 0: Project Scaffold

## Overview

Stand up a Cargo workspace with `gpuboy-wasm` as the initial crate, compile it to WASM, and load it in the browser. CI runs on every push to `main` and deploys to GitHub Pages automatically. No emulator logic — just prove the full toolchain works end to end.

## Requirements

1. WHEN Josh runs `wasm-pack build crates/gpuboy-wasm --target web`, THEN a `pkg/` directory is produced containing the compiled WASM module and JS bindings with no errors.
2. WHEN Josh opens `www/index.html` in a browser, THEN the page loads without errors and the browser console displays "gpuboy ready".
3. WHEN the WASM module fails to load, THEN the page displays a human-readable error in the DOM rather than silently failing.
4. WHEN a commit is pushed to `main`, THEN CI runs fmt check, clippy, and wasm-pack build, and fails the check if any step errors.
5. WHEN CI passes on `main`, THEN the site is automatically deployed to GitHub Pages and accessible via the repo's Pages URL.

## Acceptance Criteria

- [ ] `wasm-pack build crates/gpuboy-wasm --target web` completes without errors
- [ ] Browser console shows `gpuboy ready` on page load
- [ ] No JS console errors on page load
- [ ] Error path: if WASM import is broken, DOM shows an error message (manually break the import path to verify, then restore)
- [ ] `cargo fmt -- --check` passes with no changes
- [ ] `cargo clippy` passes with no warnings
- [ ] CI passes on push to `main` (fmt, clippy, wasm-pack build all green)
- [ ] GitHub Pages URL loads the site and shows "gpuboy ready" in console

## Design

### Architecture

```
gpuboy/                         # workspace root
  Cargo.toml                    # workspace manifest, shared lints
  crates/
    gpuboy-wasm/                # WASM entry point (cdylib)
      Cargo.toml
      src/
        lib.rs
  www/
    index.html                  # browser shell
    index.js                    # init glue: imports wasm, calls run()
  .github/
    workflows/
      ci.yml                    # lint + build + deploy to GitHub Pages
  pkg/                          # generated by wasm-pack, gitignored
```

Future crates slot in alongside `gpuboy-wasm` (e.g. `gpuboy-core` for emulator logic, `gpuboy-debugger` for tooling) and are added to the workspace `members` list.

### Key Decisions

- **Workspace from day one**: separating concerns into crates is much cheaper now than after the emulator core exists. `gpuboy-wasm` stays thin — it's just the WASM boundary. Emulation logic lives in `gpuboy-core` (Phase 1+).
- **`--target web`** over `--target bundler`: avoids requiring a bundler in Phase 0. Josh can open `index.html` via a local HTTP server with no JS build step.
- **`console_error_panic_hook`**: included from the start so Rust panics surface as readable messages in the browser console rather than cryptic WASM traps.
- **Shared lints via workspace**: `[workspace.lints.clippy]` in the root `Cargo.toml`, each crate opts in with `[lints] workspace = true`. One place to manage lint policy across all crates.
- No WebGPU in Phase 0. That's Phase 3 complexity — it would obscure the "does the toolchain work" question.

### Data Structures

None. Phase 0 has no state.

## Manual Testing

1. Run `./preflight.sh` from the repo root. Confirm it exits 0.
2. Serve the project root with `python -m http.server 8000` and open `http://localhost:8000/www/`.
3. Open DevTools → Console. Confirm "gpuboy ready" appears with no errors.
4. Temporarily edit `www/index.js` to import from a nonexistent path. Reload. Confirm a visible error message appears in the page (not just the console). Revert the edit.
5. Push to `main`. Confirm CI goes green in the Actions tab.
6. Open the GitHub Pages URL on a phone or secondary device. Confirm "gpuboy ready" appears in the mobile browser console.
