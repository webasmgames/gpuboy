# Phase 0: Project Scaffold

## Overview

Stand up the minimal Rust + wasm-pack project that compiles and loads in the browser. No emulator logic — just prove the full toolchain works end to end. A JS console message from Rust WASM is the finish line.

## Requirements

1. WHEN Josh runs `wasm-pack build`, THEN a `pkg/` directory is produced containing the compiled WASM module and JS bindings with no errors.
2. WHEN Josh opens `www/index.html` in a browser, THEN the page loads without errors and the browser console displays "gpuboy ready".
3. WHEN the WASM module fails to load, THEN the page displays a human-readable error in the DOM rather than silently failing.

## Acceptance Criteria

- [ ] `wasm-pack build --target web` completes without errors
- [ ] Browser console shows `gpuboy ready` on page load
- [ ] No JS console errors on page load
- [ ] Error path: if WASM import is broken, DOM shows an error message (manually break the import path to verify, then restore)
- [ ] `cargo fmt -- --check` passes with no changes
- [ ] `cargo clippy` passes with no warnings

## Design

### Architecture

```
gpuboy/
  Cargo.toml          # lib crate, crate-type = ["cdylib"]
  src/
    lib.rs            # wasm_bindgen entry point
  www/
    index.html        # loads the wasm module
    index.js          # init glue: imports wasm, calls init(), logs ready
  pkg/                # generated by wasm-pack, gitignored
```

No workspace yet — single crate is fine for Phase 0. Workspace can be introduced when we split into emulator core vs. wasm shell.

### Key Decisions

- **`--target web`** over `--target bundler`: avoids requiring a bundler in Phase 0. Josh can open `index.html` via a local HTTP server with no build step on the JS side.
- **`console_error_panic_hook`**: included from the start so Rust panics surface as readable messages in the browser console rather than cryptic WASM traps.
- No WebGPU in Phase 0. That's Phase 3 complexity — it requires an async device init path and shader infrastructure that would obscure the "does the toolchain work" question.

### Data Structures

None. Phase 0 has no state.

## Tasks

- [ ] 1. Create `Cargo.toml` with `crate-type = ["cdylib"]`, `wasm-bindgen` dep, and `console_error_panic_hook` dep. *(req 1)*
- [ ] 2. Write `src/lib.rs`: set panic hook on init, export a `run()` function via `#[wasm_bindgen]` that logs "gpuboy ready" to the JS console via `web_sys::console::log_1`. *(req 1, 2)*
- [ ] 3. Write `www/index.js`: async init that imports the wasm module, calls `run()`, and catches/displays any error in the DOM. *(req 2, 3)*
- [ ] 4. Write `www/index.html`: minimal shell with a `<canvas id="screen">` (160×144, scaled 3× via CSS) and a `<div id="error">` for the error path. Loads `index.js` as a module. *(req 2, 3)*
- [ ] 5. Add `pkg/` and `node_modules/` to `.gitignore`. *(housekeeping)*
- [ ] 6. Add `[lints.clippy] all = "warn"` to `Cargo.toml` to enforce clippy project-wide. *(housekeeping)*

## Manual Testing

1. From the repo root, run `wasm-pack build --target web`. Confirm it exits 0 and `pkg/` exists.
2. Serve the project root with `python -m http.server 8000` (or equivalent) and open `http://localhost:8000/www/`.
3. Open DevTools → Console. Confirm "gpuboy ready" appears with no errors.
4. Temporarily edit `www/index.js` to import from a nonexistent path. Reload. Confirm a visible error message appears in the page (not just the console). Revert the edit.
